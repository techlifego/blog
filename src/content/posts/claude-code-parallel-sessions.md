처음에는 AI 대화창 하나로 모든 일을 했다. 일정도 묻고, 기록도 정리하고, 회사 일도 의논했다. 편할 것 같았는데 대화가 길어질수록 문제가 생겼다. 앞에서 한 이야기와 뒤에서 한 이야기가 섞이고, 대화가 너무 길어지면 새 창으로 "이사"를 해야 했다.

그러다 아이와 함께 본 유튜브 영상 하나가 생각을 바꿨다. 클로드 코드(Claude Code)로 게임 스무 개를 **동시에** 만드는 영상이었다. 그날 밤 내 작업 방식을 통째로 바꿨다.

![본부와 작업장으로 나눠 일하기](/images/claude-code-parallel-sessions/cover.png)

## 이런 방법이 있다: 대화창을 일마다 따로 연다

AI는 한 대화 안에서 기억할 수 있는 양에 한계가 있다. 이걸 흔히 **컨텍스트**(맥락)라고 부른다. 대화가 길어질수록 이 공간이 차고, 차면 앞의 내용이 흐려진다.

그래서 일의 종류마다 대화창을 따로 연다. 블로그 창, 회사 일 창, 운동 기록 창, 공부 창, 컴퓨터 정리 창. 창마다 **부캐**(부캐릭터)를 하나씩 둔 셈이다. 블로그 창은 블로그 이야기만 하니 대화가 짧고 정확하다.

## 그런데 창이 많으면 누가 정리하나: 본부

창을 나누면 새 문제가 생긴다. 블로그 창이 고친 내용과 회사 일 창이 고친 내용이 **같은 파일**을 건드리면 서로 덮어쓴다. 여러 AI가 동시에 같은 파일을 고치는 것, 이게 병렬 작업에서 생기는 문제 대부분의 원인이다.

그래서 역할을 나눴다.

![본부와 작업장의 규칙](/images/claude-code-parallel-sessions/rules.png)

- **본부 창 1개**: 공용 파일(일정, 일지, 회고, 목표)을 고칠 수 있는 유일한 창.
- **작업장 창 여러 개**: 자기 폴더만 고친다. 결과는 자기 폴더의 "보고함" 파일에 적는다.
- **모으기**: 본부 창이 `/collect` 명령어 하나로 각 작업장의 보고함을 읽어 공용 파일에 반영한다.

회사로 치면 부서마다 일하고 보고서를 올리면, 본부가 모아서 전체 계획에 반영하는 구조다. 각 부서가 사장실 서류를 직접 고치지 않는다.

## 지금은 열다섯 개

처음 안내서에는 "작업장은 처음에 두세 개만"이라고 적어 두었다. 사흘 만에 이 제한을 풀었다. 일을 나누니 빨라지는 게 눈에 보였기 때문이다. 지금은 작업장 폴더가 열다섯 개다.

본부가 결과를 모을 때는, 각 작업장에서 저장한 시각을 보고 **AI 창에서 일한 시간도 자동으로 계산해** 기록한다. 어느 날은 여러 창에서 일한 시간이 모두 합쳐 6시간이 넘게 나왔다.

## 창이 많아지며 생긴 문제와 해결

| 문제 | 해결 |
|---|---|
| 창 번호가 바뀌면 AI가 어느 창인지 헷갈릴까 걱정 | 창마다 고유 번호와 주제를 함께 적은 목록을 둔다 |
| 창 제목을 자주 바꾸느라 시간이 든다 | 제목 정리는 매주 금요일에 한 번만 |
| 두 창이 비슷한 일을 하다 겹쳤다 | 겹친 두 창을 하나로 합쳤다 |
| 여러 창에 같은 말을 전했는데 어디에 전했는지 모르겠다 | 전달할 때마다 받은 창 목록을 기록하는 장부 |
| 오래 손대지 않은 창이 생긴다 | 닷새 넘게 멈춘 작업장은 일정에 25분 한 칸을 넣어 준다 |

## 시작해 보려면

처음부터 열다섯 개를 열 필요는 없다. 지금 쓰는 대화창에 이렇게 말해 보면 된다.

> 지금 이 대화에서 다루는 일을 종류별로 나눠 줘. 따로 대화창을 열면 좋을 만한 일을 두세 개 골라서, 각 창에 붙여 넣을 첫 메시지도 만들어 줘. 공용 파일은 이 창만 고치게 하고, 다른 창은 결과를 보고 파일에 적게 해 줘.

## 해 보니 알게 된 것

솔직히 말하면 창이 많아지면 **내가** 헷갈린다. 어느 창에 무슨 말을 했는지, 어느 창이 멈춰 있는지 챙기는 일이 생긴다. 그래서 창 목록과 전달 장부 같은 "관리용 파일"이 늘어났다. 일이 적은 사람이라면 창 두세 개로 충분하다.

그래도 이 방식의 가장 큰 장점은 하나다. 각 창의 대화가 짧아져서 AI가 **덜 헷갈린다.** 그리고 내가 다른 일을 하는 동안에도 여러 창이 각자 일을 해 둔다. AI를 똑똑한 비서 한 명으로 쓰다가, 작은 팀으로 쓰기 시작한 느낌이다.
